- Installation d'un compilateur C/C++ :

            - TODO

        - Penser à relancer VS Code après avoir modifié la variable d'environnement `PATH`.

          > En effet, les variables d'environnement d'un nouveau processus ne sont prises en compte qu'au lancement du processus, et reprennent l'environnement de leur processus père.
          >
          > En l'occurrence, il convient de relancer VS Code
          > pour que celui ci prenne en compte les variables d'environnement de Windows fraîchement mises à jour.

    - Sous Linux :

        - Rien de plus à faire pour `gcc`.

          L'architecture du système de fichier installe généralement les nouveaux binaires dans un répertoire déjà enregistré dans la variable d'environnement `PATH`.

          Exemple sur Ubuntu :
          ```bash
          $ cat /etc/issue
          Ubuntu 24.04.3 LTS \n \l

          $ sudo apt install gcc
          ...

          $ gcc --version
          gcc (Ubuntu 13.3.0-6ubuntu2~24.04) 13.3.0
          Copyright (C) 2023 Free Software Foundation, Inc.
          This is free software; see the source for copying  conditions.  There is NO
          warranty; not even for MERCHANTABILITY or FITNESS FOR  A PARTICULAR PURPOSE.

          $ which gcc
          /usr/bin/gcc

          $ echo $PATH
          /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin:/snap/bin:/mnt/Data/Tools/file-utils/bin
          ```

        - Pour `g++` toutefois, il semble qu'il faille redémarrer VS code, pour la prise en compte des *include paths* C++.

Après obtention d'un programme `helloworld` qui compile et s'exécute sans erreur,
noter le fichier `.vscode/tasks.json` automatiquement créé:
```json
{
    "tasks": [
        {
            "type": "cppbuild",
            "label": "C/C++: g++ build active file",
            "command": "/usr/bin/g++",
            "args": [
                "-fdiagnostics-color=always",
                "-g",
                "${file}",
                "-o",
                "${fileDirname}/${fileBasenameNoExtension}"
            ],
            "options": {
                "cwd": "${fileDirname}"
            },
            "problemMatcher": [
                "$gcc"
            ],
            "group": {
                "kind": "build",
                "isDefault": true
            },
            "detail": "Task generated by Debugger."
        }
    ],
    "version": "2.0.0"
}
```

Noter l'utilisation de l'option `-g` qui active le debugging avec `gcc` / `g++`.


# 2. Gestion d'un projet complet

L'exemple proposé reste un peu simpliste, dans la mesure où on a :
- un seul fichier source,
- une règle de build qui compile le fichier courant.

La structure usuelle d'un projet est plutôt :
- plusieurs fichier source,
- une arborescence de répertoires permettant de séparer les différents types de fichiers,
- une règle de build qui compile le programme décrit par l'ensemble des sources du projet en mode release.
- une règle de build qui compile le programme également, en mode debug.


## 2.1. Ajout de fichiers sources

Ajouter les répertoires suivants dans le projet :
- `build/`
- `doc/`
- `src/`

Déplacer le fichier `helloworld.cpp` dans le répertoire `src/`,
et supprimer le binaire généré précédemment.

Ajouter les fichiers suivants dans le répertoire `src/` :
```C++
// whoami.h

#ifndef _WHOAMI_H_
#define _WHOAMI_H_

const char* const whoami();

#endif
```

```C++
// whoami.cpp

#include "whoami.h"

const char* const whoami() {
    return "you";
}
```

Modifier le fichier `helloworld.cpp` comme suit:
```C++
// helloworld.cpp

#include <iostream>
#include "whoami.h"

int main()
{
    std::cout << "Hello " << whoami() << "!" << std::endl;
}
```

Modifier le fichier `.vscode/tasks.json`:
- Modifier le *label* de la tache de `C/C++: g++ build active file` en `C/C++: g++ build helloworld (debug)`
  pour indiquer dans le nom qu'on compile désormais le programme principal du projet,
  et non plus le fichier courant.
- Modifier la liste des fichiers source de `"${file}"` à `"src/*.cpp"`.
- Modifier la destination du binaire de sortie (après l'option `-o`)
  de `"${fileDirname}/${fileBasenameNoExtension}"`
  en `"build/helloworld.debug.exe"`
  pour générer dans le répertoire `build/`.
- Modifier la ligne *detail* de `Task generated by Debugger.` en `Compile in Debug mode.` pour expliciter l'objet de la tache de build.


## 2.2. Ajout d'une configuration d'exécution

Sélectionner un fichier .cpp, et appuyer sur F5 :
- Notre tache ne permet plus d'exécution implicite.
- Sélectionner l'option "Open 'launch.json'" pour pouvoir créer une configuration d'exécution explicite.
    - Un fichier `.vscode/launch.json` est créé.
- Run > Add Configurations...
- Sélectionner l'option "C/C++: (gdb) Launch".
- Ajuster les paramètres comme suit :
    - *program* : `${workspaceFolder}/build/helloworld.debug.exe`
      pour expliciter le programme à exécuter.
    - *cwd* : `${workspaceFolder}/build`
      pour utiliser le répertoire `build/` comme répertoire courant d'exécution.

Appuyer sur F5, à partir de n'importe quel fichier :
VS Code lance le programme et affiche "Hello you!".


## 2.3. Recompiler automatiquement avant exécution

Modifier Le fichier `whoami.cpp`
pour modifier le texte renvoyé par la fonction `whoami()`,
puis appuyer sur F5 :
- Le programme affiche toujours "Hello you!".

Dans le fichier `.vscode/launch.json`,
ajouter l'option `"preLaunchTask": "C/C++: g++ build helloworld (debug)"` dans notre configuration.

Appuyer sur F5 :
- La compilation du programme est lancée.
- L'exécution du programme prend en compte la modification du fichier `whoami.cpp`.
